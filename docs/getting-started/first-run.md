# 5분 첫 실행

> 공식 문서: [Claude Code 빠른 시작](https://docs.anthropic.com/en/docs/claude-code/quickstart) · [Cursor 빠른 시작](https://docs.cursor.com/en/get-started/quickstart) · [ChatGPT 빠른 시작](https://learn.chatgpt.com/docs/quickstart) · [Copilot 빠른 시작](https://docs.github.com/en/copilot/get-started/quickstart)

첫 작업은 코드를 쓰게 하지 말고 **작은 범위를 읽고 근거를 대게** 하세요. 에이전트가 무엇을 볼 수 있는지 확인하는 데 5분이면 충분합니다.

## 0:00–1:00 · 안전한 재료 고르기

- 비밀값, 고객 정보, 미공개 계약이 없는 작은 프로젝트나 공개 문서 하나를 고릅니다.
- Git 저장소라면 변경 사항이 없는지 먼저 확인합니다.
- 에이전트에는 해당 폴더나 필요한 파일만 연결합니다.

## 1:00–3:00 · 첫 요청 보내기

아래 프롬프트에서 대괄호만 바꿉니다. 코드블록 오른쪽의 복사 버튼으로 그대로 가져갈 수 있습니다.

```text
이 프로젝트를 수정하지 말고 읽기만 해줘.

1. [확인할 기능]이 시작되는 파일을 찾아라.
2. 주요 흐름을 5단계 이내로 설명하라.
3. 각 설명 옆에 근거 파일 경로를 붙여라.
4. 확실하지 않은 내용은 추측하지 말고 "확인 필요"로 표시하라.
```

## 3:00–4:00 · 근거 확인하기

에이전트가 제시한 파일 두 개를 직접 엽니다. 파일이 없거나 내용과 설명이 다르면 바로 정정 요청을 합니다.

```text
[파일 경로]의 실제 내용과 방금 설명이 일치하는지 다시 대조해줘.
불일치하면 원인을 말하고 설명만 수정해. 파일은 바꾸지 마.
```

## 4:00–5:00 · 작은 변경과 검증

연습용 브랜치나 버려도 되는 샘플에서만 한 줄짜리 변경을 맡깁니다.

```text
[문서 또는 테스트 파일]에만 한정해서 [작은 변경]을 해줘.
변경 전 계획, 변경 diff, 실행한 검증과 결과를 순서대로 보여줘.
다른 파일은 수정하지 마.
```

## 성공 기준

- 연결한 범위 안에서 근거 파일을 정확히 찾았다.
- 요청하지 않은 파일을 바꾸지 않았다.
- 변경 내용과 검증 결과를 사람이 다시 확인할 수 있다.
- 실패하거나 모르는 내용을 숨기지 않았다.

하나라도 어긋나면 더 큰 권한을 주기 전에 [오류 해결](/integrations/troubleshooting)과 해당 제품의 셋업 문서를 확인하세요.
