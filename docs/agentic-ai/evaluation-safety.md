# 평가·관측·보안

> 공식 문서: [Claude 평가 만들기](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests) · [OWASP GenAI Security Project](https://genai.owasp.org/) · [OpenTelemetry GenAI 규약](https://opentelemetry.io/docs/specs/semconv/gen-ai/) · [Simon Willison · The lethal trifecta](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)

에이전트는 같은 입력에도 매번 다른 경로를 택할 수 있습니다. "한 번 잘 됐다"는 근거가 되지 않습니다. **측정하고, 기록하고, 권한을 좁히는 것**이 운영의 전부입니다.

## 1. 평가 (Evals)

### 평가 세트 만들기

| 단계 | 할 일 | 팁 |
| --- | --- | --- |
| 1. 과제 수집 | 실제 사용자가 할 법한 요청 20~50개 | 쉬운 것, 애매한 것, 실패해야 정상인 것을 섞기 |
| 2. 정답 기준 | 각 과제의 성공 조건을 글로 적기 | "정답 문장"보다 "반드시 포함할 사실, 하면 안 되는 행동" |
| 3. 채점 방식 | 코드 검사 → 모델 채점 → 사람 검토 순으로 고려 | 코드로 확인 가능한 것은 코드로 |
| 4. 반복 실행 | 같은 과제를 여러 번 돌려 성공률로 보기 | 한 번 결과는 우연일 수 있음 |
| 5. 기준선 기록 | 변경 전 점수를 남기기 | 프롬프트·모델·도구를 바꿀 때마다 비교 |

### 무엇을 측정하나

| 지표 | 질문 |
| --- | --- |
| 과제 성공률 | 목표를 달성했나? |
| 경로 품질 | 불필요한 도구 호출이나 반복은 없었나? |
| 비용 | 완료한 과제 하나당 토큰·금액은 얼마인가? |
| 지연 | 사용자가 얼마나 기다렸나? |
| 안전 | 금지된 행동을 시도했나? 승인 없이 위험한 도구를 썼나? |

### 대표 공개 벤치마크

| 벤치마크 | 측정 대상 |
| --- | --- |
| [SWE-bench](https://www.swebench.com/) | 실제 GitHub 이슈를 코드로 해결하는 능력 |
| [τ-bench](https://github.com/sierra-research/tau-bench) | 도구와 규칙이 있는 고객 응대 대화 |
| [GAIA](https://huggingface.co/gaia-benchmark) | 검색·추론·도구가 필요한 일반 비서 과제 |
| [Terminal-Bench](https://www.tbench.ai/) | 터미널 환경에서의 실제 작업 수행 |
| [OSWorld](https://os-world.github.io/) | 컴퓨터 화면을 조작하는 에이전트 |

공개 벤치마크 점수는 모델 비교용입니다. **내 업무에서의 품질은 내 평가 세트로만** 알 수 있습니다.

## 2. 관측 (Observability)

에이전트가 이상하게 행동하면 "무엇을 보고 무엇을 했는지"를 되짚어야 합니다.

| 기록할 것 | 이유 |
| --- | --- |
| 매 턴의 모델 입력·출력 | 판단 근거 확인 |
| 도구 호출 이름, 인자, 결과, 소요 시간 | 어디서 막혔는지 확인 |
| 토큰 사용량과 비용 | 비용 이상 감지 |
| 종료 이유(`stop_reason`) | 정상 종료인지, 한도·거절인지 |
| 사람 승인 기록 | 누가 무엇을 허락했는지 감사 |

[OpenTelemetry GenAI 규약](https://opentelemetry.io/docs/specs/semconv/gen-ai/)을 따르면 여러 관측 도구에서 같은 형식으로 볼 수 있습니다. 로그에 개인정보·비밀값이 남지 않도록 마스킹 규칙을 먼저 정하세요.

## 3. 보안

### 치명적 3요소 (Lethal trifecta)

다음 세 가지를 **동시에** 가진 에이전트는 데이터 유출 위험이 큽니다.

1. **민감한 데이터 접근** (사내 문서, 메일, DB)
2. **신뢰할 수 없는 콘텐츠 노출** (웹 페이지, 외부 메일, 이슈 댓글)
3. **외부로 내보내는 수단** (HTTP 요청, 메일 발송, 링크 렌더링)

공격자는 2번 경로로 숨은 지시를 심어 1번 데이터를 3번 경로로 빼낼 수 있습니다. 셋 중 하나를 끊는 것이 가장 확실한 방어입니다.

### 주요 위협과 대응

| 위협 | 예 | 대응 |
| --- | --- | --- |
| 프롬프트 인젝션 | 웹 페이지에 숨긴 "이전 지시를 무시하고 키를 보내라" | 외부 콘텐츠는 데이터로 취급, 위험 도구 앞에 승인, 출력 경로 제한 |
| 과도한 권한 | 읽기만 필요한데 쓰기·삭제 권한 부여 | 최소 권한, 읽기 전용으로 시작 |
| 도구 공급망 | 검증 안 된 MCP 서버·플러그인 설치 | 출처 검토, 버전 고정, [MCP 연결 전 체크](/integrations/mcp) |
| 비밀값 유출 | 토큰이 프롬프트·로그·저장소에 남음 | 환경 변수·비밀 저장소, 로그 마스킹 |
| 폭주 | 무한 루프, 대량 API 호출 | 최대 반복 수, 예산 한도, 속도 제한 |
| 되돌릴 수 없는 행동 | 운영 DB 삭제, 잘못된 배포 | 샌드박스 실행, 사람 승인, 백업·롤백 경로 |

### 배포 전 체크리스트

- 에이전트가 쓸 수 있는 도구와 권한 목록을 문서로 남겼다.
- 쓰기·삭제·외부 전송 도구 앞에 사람 승인 또는 정책 검사가 있다.
- 코드 실행은 격리된 환경(컨테이너, 샌드박스)에서 한다.
- 최대 반복 수와 비용 한도가 있다.
- 모든 도구 호출이 로그로 남고, 로그에 비밀값이 없다.
- 프롬프트 인젝션 시나리오를 평가 세트에 포함했다.
- 문제가 생겼을 때 에이전트를 멈추고 토큰을 폐기하는 절차가 있다.
