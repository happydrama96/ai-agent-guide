# 사내 문서 연결

> 공식 문서: [Claude Code 데이터 사용](https://docs.anthropic.com/en/docs/claude-code/data-usage) · [Cursor 개인정보와 보안](https://docs.cursor.com/account/privacy) · [ChatGPT 권한](https://learn.chatgpt.com/docs/permissions) · [GitHub Copilot 데이터 보호](https://docs.github.com/en/copilot/responsible-use/copilot-trust-center)

연결의 목표는 “문서를 많이 넣는 것”이 아니라 **누가 볼 수 있는 최신 원문을, 필요한 작업에만 제공하는 것**입니다.

## 연결 방식 선택

| 방식 | 추천 상황 | 장점 | 주의점 |
| --- | --- | --- | --- |
| 필요한 파일만 첨부 | 일회성 요약·비교 | 범위가 가장 분명함 | 새 버전이 생겨도 자동 갱신되지 않음 |
| 프로젝트 폴더 연결 | 코드와 가까운 Markdown 문서 | Git 이력과 리뷰 가능 | 저장소 접근자에게 문서도 노출될 수 있음 |
| 공식 커넥터·플러그인 | 자주 바뀌는 팀 문서 | 검색과 최신성 유지가 쉬움 | 관리자 정책과 OAuth scope 확인 필요 |
| 사내 MCP 서버 | 여러 시스템을 통제해 제공 | 권한·감사·도구를 중앙 관리 | 서버 운영, 보안 검토, 장애 대응 필요 |

## 권장 구조

공개 가능한 사용 지침은 저장소의 `docs/`나 에이전트 지침 파일에 둡니다. 제한 문서는 원래 문서 시스템에 남기고, 커넥터 또는 MCP가 현재 사용자의 권한으로만 검색하게 합니다. 비밀값과 원문 전체를 프롬프트 템플릿에 복사하지 않습니다.

## 연결 전 분류

| 등급 | 예시 | 기본 처리 |
| --- | --- | --- |
| 공개 | 공개 매뉴얼, 오픈소스 문서 | 연결 가능, 출처 표시 |
| 사내 | 회의록, 운영 절차, 미공개 로드맵 | 승인된 회사 워크스페이스와 최소 대상만 |
| 제한 | 고객 정보, 계약, 인사·재무 자료 | 담당자 승인과 제품별 보존·학습 정책 확인 전 연결 금지 |
| 비밀 | API 키, 개인 키, 비밀번호 | 문서·프롬프트에 넣지 않고 비밀 저장소 사용 |

## 실제 운영 흐름

1. 원본 시스템의 소유자와 보안 등급을 확인합니다.
2. 읽기 전용 계정이나 최소 OAuth scope로 연결합니다.
3. 테스트 문서 한 건을 제목과 수정일로 찾습니다.
4. 권한 없는 문서가 검색되지 않는지 별도 계정으로 확인합니다.
5. 답변마다 문서 제목·경로·수정일을 달도록 프로젝트 지침에 넣습니다.
6. 분기마다 미사용 연결과 토큰을 정리합니다.

## 프로젝트 지침 예시

```text
사내 문서를 사용할 때 다음을 지켜라.
- 연결된 문서에서 확인한 사실만 답하고, 추측은 "확인 필요"로 표시한다.
- 답변마다 문서 제목, 원본 경로, 최종 수정일을 붙인다.
- 서로 충돌하면 더 최신 문서를 우선하지 말고 충돌 사실과 두 출처를 모두 보여준다.
- 고객정보, 자격 증명, 개인식별정보를 출력하거나 다른 도구로 전달하지 않는다.
- 쓰기, 공유, 발송은 반드시 실행 전에 사람의 승인을 받는다.
```

## 최신성 검증

“검색됨”과 “최신임”은 다릅니다. 답변의 근거 문서를 열어 상태가 폐기·초안인지, 상위 정책과 충돌하지 않는지 확인합니다. 같은 제목의 복제 문서가 많다면 문서 소유자와 정식 원본 경로를 먼저 정리하는 편이 연동보다 효과가 큽니다.

## 연결 해제

제품의 **설정 → 연결/앱 → 해당 서비스 → 연결 해제** 후 원본 시스템의 **계정 → 연결된 앱 → 접근 취소**도 수행합니다. MCP라면 클라이언트 설정 제거, 서버 계정 비활성, 발급 토큰 폐기, 로그의 비밀값 노출 여부 확인까지 한 묶음으로 처리합니다.
