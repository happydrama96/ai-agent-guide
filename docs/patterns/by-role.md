# 직군별 실전 시나리오

> 공식 문서: [ChatGPT·Codex 활용 사례](https://learn.chatgpt.com/use-cases) · [Claude Code 일반 워크플로](https://docs.anthropic.com/en/docs/claude-code/common-workflows) · [Cursor 가이드](https://docs.cursor.com/en/guides) · [GitHub Copilot 프롬프트 안내](https://docs.github.com/en/copilot/concepts/prompting/prompt-engineering)

좋은 시나리오는 “AI가 무엇을 하느냐”보다 **입력, 산출물, 완료 조건, 사람의 승인 지점**이 선명합니다.

## 개발 · 낯선 기능 추적 후 작은 수정

**입력:** 이슈, 관련 저장소, 재현 절차  
**산출물:** 근거 파일, 수정 diff, 테스트 결과  
**사람의 승인:** 구현 계획과 최종 diff

```text
목표: [이슈]의 원인을 찾고 최소 변경으로 고친다.

먼저 수정하지 말고:
1. 재현 경로를 확인한다.
2. 관련 파일과 호출 흐름을 근거 경로와 함께 제시한다.
3. 원인 가설과 반증 방법을 쓴다.
4. 수정할 파일, 하지 않을 변경, 실행할 테스트를 계획한다.

내가 계획을 승인한 뒤에만 수정한다.
수정 후에는 diff 요약, 실행한 검증, 남은 위험을 보고한다.
```

**검수:** 요청 밖 리팩터링이 섞이지 않았는지, 실패 테스트를 지우지 않았는지, 실행하지 않은 검증을 실행했다고 말하지 않는지 봅니다.

## 기획 · 인터뷰에서 요구사항 초안 만들기

**입력:** 익명화한 인터뷰 메모, 제품 원칙, 기존 정책  
**산출물:** 문제·근거·가설·미확인 질문 표  
**사람의 승인:** 우선순위와 정책 판단

```text
첨부한 인터뷰를 제품 요구사항의 근거로 정리해줘.

- 사용자의 직접 관찰, 해석, 제안을 서로 다른 열로 분리한다.
- 빈도와 중요도를 혼동하지 않는다.
- 각 항목에 근거 문서와 위치를 붙인다.
- 개인정보는 다시 노출하지 않는다.
- 상충하는 의견과 표본 한계를 별도 섹션에 둔다.
- 마지막에 추가로 확인할 질문 5개만 제시한다.
```

**검수:** 소수 의견이 전체 사용자처럼 확대되지 않았는지, 인용과 해석이 섞이지 않았는지, 정책을 AI가 임의 결정하지 않았는지 봅니다.

## 디자인 · UI 문구 일관성 점검

**입력:** 화면 문구 목록, 보이스 가이드, 금칙어  
**산출물:** 문제 유형별 수정 제안과 이유  
**사람의 승인:** 최종 문구와 접근성

```text
첨부한 UI 문구를 보이스 가이드와 대조해줘.

표 컬럼: 위치 | 현재 문구 | 문제 유형 | 제안 | 근거 규칙
문제 유형은 용어 불일치, 행동 불명확, 오류 복구 부족, 접근성, 길이로 제한한다.
의미가 바뀌거나 정책 확인이 필요한 문구는 고치지 말고 "확인 필요"로 표시한다.
새로운 제품 기능을 추측하지 않는다.
```

**검수:** 에이전트가 화면 동작을 추측하지 않았는지, 번역 길이와 스크린리더 맥락을 담당자가 확인했는지 봅니다.

## 운영 · 장애 타임라인과 인수인계

**입력:** 비밀값을 제거한 로그, 알림 시각, 배포 기록, 런북  
**산출물:** 사실 타임라인, 가설, 다음 행동  
**사람의 승인:** 운영 명령 실행과 대외 공지

```text
제공한 로그와 배포 기록으로 장애 타임라인을 작성해줘.

- 사실과 추론을 분리한다.
- 모든 시각을 [Asia/Seoul]로 정규화하고 원래 시간도 보존한다.
- 각 사실에 근거 파일과 줄 또는 이벤트 ID를 붙인다.
- 누락 구간과 상충하는 기록을 표시한다.
- 운영 명령, 롤백, 공지는 실행하지 말고 제안만 한다.
- 마지막에 다음 교대자가 확인할 항목을 우선순위로 정리한다.
```

**검수:** 시간대 변환, 로그 누락, 상관관계와 원인의 혼동을 확인하고 운영 변경은 반드시 권한자가 실행합니다.

## 공통 완료 체크리스트

- 입력 자료의 보안 등급과 공유 허용 범위를 확인했다.
- 사실, 추론, 제안이 구분돼 있다.
- 파일·문서·로그 등 근거 위치를 사람이 열어 봤다.
- 변경·발송·배포는 diff나 미리보기 뒤 사람이 승인했다.
- 실패, 미확인, 남은 위험이 결과에 포함돼 있다.
- 작업이 끝난 뒤 불필요한 파일·연결·토큰을 정리했다.
