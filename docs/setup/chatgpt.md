# ChatGPT 셋업

> 공식 문서: [빠른 시작](https://learn.chatgpt.com/docs/quickstart) · [프로젝트와 대화](https://learn.chatgpt.com/docs/projects) · [파일 작업](https://learn.chatgpt.com/docs/artifacts-viewer) · [플러그인](https://learn.chatgpt.com/docs/plugins) · [Windows 앱](https://learn.chatgpt.com/docs/windows/windows-app)

## 한 줄 요약

코드 전용 도구라기보다 조사·파일 분석·문서 산출물을 한 프로젝트에 묶는 범용 작업 공간으로 접근하면 좋습니다.

## 이런 사람에게

- 기획서, 리서치, 표, 발표 자료처럼 코드 밖 산출물이 많은 사람
- 여러 파일과 대화를 같은 주제로 계속 이어가려는 사람
- 저장소를 직접 편집하고 테스트하는 흐름이 핵심이면 Claude Code·Cursor·Copilot이 더 적합할 수 있습니다.

## 설치

웹은 설치 없이 [ChatGPT](https://chatgpt.com/)에서 사용합니다. 데스크톱 앱은 macOS, Windows, Linux용이 있으며 [공식 다운로드](https://chatgpt.com/download/) 또는 [빠른 시작](https://learn.chatgpt.com/docs/quickstart)의 운영체제별 안내에서 받습니다. 데스크톱 앱 한 곳에서 **Chat**(빠른 질문), **Work**(조사·산출물), **Codex**(소프트웨어 개발)를 전환해 씁니다. 회사 장비에서는 **설정 → 앱 → 설치 허용 정책**과 조직 배포 지침을 먼저 확인하세요.

| 명령어 | 하는 일 | 언제 쓰나 |
| --- | --- | --- |
| `winget install --id 9PLM9XGG6VKS -s msstore` | Windows에서 Microsoft Store 패키지로 데스크톱 앱 설치 | 브라우저 다운로드 대신 터미널로 설치할 때 |

조직 단위 Windows 배포는 [Windows 앱 배포](https://learn.chatgpt.com/docs/enterprise/windows-deployment) 문서를 따릅니다.

## 인증

앱 또는 웹에서 **로그인 → 계정 방식 선택 → 조직 선택** 순서로 진행합니다. 개인 공간과 회사 워크스페이스가 함께 보이면 대화를 시작하기 전에 현재 워크스페이스를 확인합니다. 공유 PC에서는 사용 후 **프로필 → 설정 → 보안 → 모든 기기에서 로그아웃** 경로를 검토하세요.

API 키는 ChatGPT 웹 로그인 수단이 아닙니다. 데스크톱 앱의 Codex는 API 키로도 쓸 수 있지만 일부 기능(예: 일부 플러그인)이 제한될 수 있으므로 기본은 ChatGPT 계정 로그인입니다. API Platform의 결제와 ChatGPT 구독도 별도일 수 있으므로 혼동하지 않습니다.

## 프로젝트 연결

ChatGPT에서 **사이드바 → 새 프로젝트 → 프로젝트 이름 → 파일 추가 → 프로젝트 지침** 순서로 구성합니다. 프로젝트 화면은 대화 목록인 **Chats**와 업로드 파일·연결 자료를 모은 **Sources**로 나뉘며, 같은 프로젝트에 Chat과 Work 대화를 함께 둘 수 있습니다. 필요한 파일만 올리고 원본의 보안 등급과 보존 정책을 확인하세요. ChatGPT 프로젝트는 내 컴퓨터 폴더에 직접 접근하지 않으므로, 쓸 자료는 업로드하거나 연결해야 합니다. 프로젝트에 올린 파일은 로컬 폴더와 자동 동기화되는 Git 저장소가 아니므로 최신 원본 여부를 사람이 관리해야 합니다.

데스크톱 앱의 Codex·Work에서는 폴더를 열어 그 안의 파일을 읽고 수정하게 할 수 있습니다. 프로젝트에 로컬 폴더를 붙일 때는 **프로젝트 메뉴 → Edit project → Add folder**를 쓰고, 기본 작업 폴더는 해당 폴더의 **Make primary**로 바꿉니다. 새 대화는 기본 폴더에서 시작하며, 보조 폴더의 `AGENTS.md`나 Skills는 자동으로 읽히지 않습니다. 현재 제품 화면의 권한 설명을 읽고 필요한 범위만 허용하세요. 기능 제공 여부는 요금제·운영체제·워크스페이스 정책에 따라 다를 수 있습니다.

## 자주 쓰는 명령어

| 명령어 | 하는 일 | 언제 쓰나 |
| --- | --- | --- |
| `새 프로젝트` | 대화, 파일, 지침을 주제별로 묶기 | 반복 업무나 장기 작업을 시작할 때 |
| `프로젝트 → 파일 추가` | 근거 자료를 프로젝트 컨텍스트에 넣기 | 여러 대화에서 같은 자료를 쓸 때 |
| `프로젝트 → 지침` | 출력 형식과 역할을 지속 적용 | 매번 같은 요구를 반복하고 싶지 않을 때 |
| `대화 → … → 프로젝트로 이동` | 기존 대화를 프로젝트에 포함 | 흩어진 관련 대화를 정리할 때 |
| `새 대화` | 같은 프로젝트 안에서 컨텍스트를 분리 | 주제가 달라져 대화가 길어졌을 때 |
| `프로젝트 메뉴 → Edit project → Add folder` | 데스크톱 프로젝트에 로컬 작업 폴더 추가 | Codex·Work가 실제 파일을 읽고 수정해야 할 때 |
| `Plugins → 검색 → +` | 플러그인 설치와 외부 서비스 연결 | 승인된 업무 도구의 자료나 기능이 필요할 때 |

## 잘하는 것·못하는 것

### 잘하는 것

- 여러 문서의 공통점·차이·누락을 표로 정리하는 일
- 초안을 만들고 독자·톤·분량에 맞춰 반복 수정하는 일
- 출처가 있는 웹 조사와 파일 기반 질문을 결합하는 일

### 못하는 것

- 업로드하지 않았거나 연결하지 않은 사내 최신 문서를 자동으로 아는 일
- 출처가 없는 숫자·정책·법률 판단의 정확성을 보장하는 일
- 일반 프로젝트만으로 로컬 저장소를 Git처럼 동기화하고 테스트하는 일

## 흔한 오류

| 증상 | 먼저 볼 것 | 해결 |
| --- | --- | --- |
| 파일 내용을 못 찾음 | 파일이 현재 프로젝트에 있고 지원 형식·용량인지 | 파일을 다시 추가하고 새 대화에서 파일명을 지정해 질문 |
| 이전 지침을 따르지 않음 | 현재 대화가 올바른 프로젝트 안인지 | **프로젝트 → 지침**을 짧고 충돌 없이 정리하고 새 대화에서 확인 |
| 회사 자료 연결 메뉴가 없음 | 요금제와 관리자 허용 정책 | **Plugins** 탭에서 해당 플러그인이 보이는지 확인하고, 없으면 관리자에게 **Admin console → Plugins**의 설치 정책과 **Permissions & roles**의 플러그인 사용 권한 확인을 요청 |
| 플러그인이 웹에서 설치되지 않음 | 상세 화면의 **Desktop only** 표시 | 데스크톱 앱에서 설치·사용 |
| 로그인이 반복됨 | 브라우저 쿠키·SSO·시스템 시간 | 공식 상태 페이지와 조직 SSO를 확인하고 앱을 최신판으로 갱신 |
| 답변이 그럴듯하지만 틀림 | 인용한 원문과 숫자 | 근거 위치를 요구하고 원문과 대조한 뒤 중요한 판단은 담당자가 승인 |
