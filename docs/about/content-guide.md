# 콘텐츠 관리 규칙

> 공식 문서: [Docusaurus Markdown 기능](https://docusaurus.io/docs/markdown-features) · [문서 메타데이터](https://docusaurus.io/docs/api/plugins/@docusaurus/plugin-content-docs#markdown-front-matter)

이 규칙은 기능이 바뀌어도 문서가 덜 낡고, 독자가 실행 결과를 직접 확인하게 만드는 최소 기준입니다.

## 새 문서 체크리스트

- 상단에 벤더 공식 문서 링크를 둔다.
- 화면 캡처 대신 **설정 → 계정 → 연결**처럼 텍스트 경로를 쓴다.
- 명령어는 `명령어 | 하는 일 | 언제 쓰나` 표에 쓴다.
- 프롬프트와 설정은 복사 가능한 fenced code block으로 쓴다.
- 성공 기준, 실패 증상, 되돌리는 방법을 포함한다.
- 하단에 `최종 확인일 / 기준 버전`을 쓴다.
- 가격과 제한은 고정 숫자로 옮기지 말고 공식 페이지로 보낸다.

## 셋업 문서 고정 목차

아래 순서를 바꾸지 않습니다.

1. 한 줄 요약
2. 이런 사람에게
3. 설치
4. 인증
5. 프로젝트 연결
6. 자주 쓰는 명령어
7. 잘하는 것·못하는 것
8. 흔한 오류

## 템플릿

`docs/_templates/`에 시작하기, 셋업, 연동, 레퍼런스, 활용 패턴, 업데이트 템플릿이 있습니다. 이 경로는 사이트 빌드에서 제외되므로 복사한 뒤 공개 섹션으로 옮기고 실제 공식 링크와 검증 날짜를 채웁니다.

## 업데이트 절차

| 명령어 | 하는 일 | 언제 쓰나 |
| --- | --- | --- |
| `npm run start` | 수정 중 로컬 미리보기 | 문서를 쓰며 링크와 표를 확인할 때 |
| `npm run build` | 전체 정적 빌드와 깨진 링크 검사 | PR 또는 배포 전 |
| `npm run serve` | 빌드 산출물 미리보기 | 검색과 경로를 배포 형태로 확인할 때 |

변경한 제품의 셋업, 치트시트, MCP, 업데이트 문서를 함께 검색해 같은 명령이나 경로가 중복돼 있지 않은지 확인합니다.
